# 🧠 Smart Q&A Service (RAG)

A FastAPI web service that answers user questions from a knowledge base using RAG (Retrieval-Augmented Generation). Questions are embedded with a multilingual Sentence Transformers model, matched against a **ChromaDB** vector store, and answered in Persian by an LLM through any **OpenAI-compatible API**. Questions it can't answer become tickets for a human operator, and operator answers flow back into the knowledge base.

## ✨ Features

- **RAG core:** semantic search (cosine similarity) over ChromaDB, with answers generated by an LLM from the retrieved context only.
- **Automatic tagging:** each question is classified into one of the configured support categories.
- **Ticketing:** unanswered questions and answers users mark as wrong become pending tickets.
- **Feedback loop:** positive feedback and operator answers are added to the knowledge base.
- **Protected admin API:** knowledge base and ticket endpoints require an admin token.
- **Automatic API docs** at `/docs`.

## 🚀 Getting Started

### Prerequisites

- Python 3.9+

### 1. Install

```bash
git clone https://github.com/chiizzzz/smart-qna-service.git
cd smart-qna-service
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate
pip install -r requirements.txt
```

### 2. Configure

```bash
cp .env.example .env
```

Set at least `OPENAI_API_KEY` and `ADMIN_API_KEY`. If `ADMIN_API_KEY` is empty, every admin endpoint returns `503`.

### 3. Run

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### 4. Load the knowledge base

The ChromaDB store (`./chroma_db_store`) is created on first run and is not committed to git. Fill it either through the admin API (below) or from a JSON file containing a list of `{"question": ..., "answer": ...}` objects:

```bash
python -m scripts.import_knowledge_base path/to/data.json            # append
python -m scripts.import_knowledge_base path/to/data.json --overwrite
```

The old `vector_store.json` inside `New folder/app.zip` works as input.

## ⚙️ API

### Public endpoints

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/v1/qna` | Ask a question: `{"query": "..."}` |
| `POST` | `/api/v1/feedback` | Rate an answer: `{"session_id": "...", "is_correct": true}` |

`/qna` returns either an answer:

```json
{
  "session_id": "…",
  "tags_identified": ["فروش و قیمت‌گذاری"],
  "final_answer": "…",
  "retrieved_context_count": 1,
  "original_question": "…"
}
```

or, when nothing relevant is found, a ticket:

```json
{"status": "ticket_created", "message": "…", "question_id": "…"}
```

### Admin endpoints (header `X-Admin-Token: <ADMIN_API_KEY>`)

| Method | Path | Description |
|---|---|---|
| `POST` | `/api/v1/admin/knowledge_base/add` | Add Q&A pairs: `{"data": [{"question": "...", "answer": "..."}]}` |
| `POST` | `/api/v1/admin/knowledge_base/add_from_operator` | Add a single pair: `{"question": "...", "answer": "..."}` |
| `PUT` | `/api/v1/admin/knowledge_base/overwrite` | Replace the whole knowledge base |
| `DELETE` | `/api/v1/admin/knowledge_base/delete` | Delete by `{"ids": [...]}`, or everything when no ids are sent |
| `GET` | `/api/v1/admin/knowledge_base/all` | List all entries |
| `GET` | `/api/v1/admin/pending_tickets` | List pending tickets |
| `POST` | `/api/v1/admin/respond_to_ticket` | Answer a ticket: `{"question_id": "...", "answer": "..."}` |

### Example

```bash
curl -X POST -H "Content-Type: application/json" \
  -d '{"query": "How are trip costs calculated?"}' \
  http://127.0.0.1:8000/api/v1/qna
```

## 🔧 Configuration notes

- `SIMILARITY_THRESHOLD` is a cosine similarity (default `0.75`). A collection created before this change uses ChromaDB's default L2 space; the service detects this and converts distances, so old data keeps working. To switch it to cosine, re-import with `--overwrite`.
- `LLM_MAX_TOKENS` (default `512`) caps the answer length.
